### 1. 区别问数项目与智库项目

问数是对着数据库提问，比如“去年卖了多少钱”，系统生成 SQL 查结果。智库通常是对着文档提问，先找相关内容，再整理成答案。

### 2. 区别数据仓库与业务数据库？

业务数据库管日常业务，比如下单、付款，增删改比较多；数据仓库把各处的数据整理到一起，主要用来做统计和分析，也会保留历史数据。

### 3. 说说问数项目的2个阶段

第一阶段是建知识库，把表、字段、指标和字段取值整理好，建立检索索引。第二阶段是在线问数，根据问题找相关信息，生成 SQL，校验后执行并返回结果。

### 4. 区别一下json与yaml

JSON 用大括号和中括号组织数据，格式严格，常用于接口传数据；YAML 靠缩进表示层级，支持注释，写配置更方便。

### 5. 说说OmegaCof库的2个作用

这里指 OmegaConf。项目里主要做两件事：读取 YAML 配置；结合 dataclass 定义检查配置类型，并转成可以用点号访问属性的配置对象。

### 6. GIT管理项目的基本操作

`git init` 初始化，或用 `git clone` 拉取项目；改完用 `git status`、`git diff` 查看，再用 `git add`、`git commit` 提交。`git pull` 拉更新，`git push` 推送，`git switch -c` 新建分支。

### 7. 后端项目的三层架构

接口层接收请求、返回结果；业务层处理具体业务；持久层负责读写数据库。一般是接口层调用业务层，业务层再调用持久层。

### 8. 说说SQLAlchmy库的特点

SQLAlchemy 是 Python 操作数据库的库，既能写 SQL，也能用 ORM 把表映射成类。它还提供连接池、事务管理，并支持异步访问。

### 9. 说说SQLAlchmy库中的下面几个配置的作用

- `pool_size`：连接池常驻连接的上限，连接按需创建。
- `max_overflow`：常驻连接不够用时，最多再开多少个临时连接。
- `autoflush`：是否在查询等操作前自动把 ORM 的待处理改动发给数据库；flush 不等于提交，设为 False 后 commit 仍会触发 flush。
- `autobegin`：是否在需要访问数据库等操作时自动开始事务。

### 10. 说说Qdrant的作用

Qdrant 是向量数据库，用来找语义相近的内容。项目里用于检索字段和指标，比如用户说“营业额”，也能尝试找到“销售额”。

### 11. 说说Hugging Face的作用

Hugging Face 提供模型、数据集和相关工具。项目里通过它的嵌入接口把文字转成向量，方便后续做语义检索。

### 12. 说说ContextVar的理解

ContextVar 用来保存当前执行上下文里的变量，适合异步任务。项目里用它存请求 ID，让不同请求的日志能各自对应，不会混在一起；用完可以通过 token 恢复原值。

### 13. 说说日志模块的功能特点

项目用 Loguru 记录日志，可以按级别输出到控制台和文件，显示时间、代码位置和请求 ID，还支持日志文件切分和过期清理，方便排查问题。

### 14. 说说你对ES的理解

ES 就是 Elasticsearch，主要做全文搜索。它把文本分词后建立倒排索引，方便按关键词找内容；项目里用它搜索字段的实际取值，比如商品名、地区名。

### 15. ES中的索引、文档和字段

索引是一组文档的集合，可以粗略理解成表；文档是一条 JSON 数据，类似一行记录；字段就是文档里的属性，比如商品名和地区。

### 16. 什么是REST API

REST API 是一种设计接口的方式：用 URL 表示资源，用 HTTP 方法表示操作，比如 GET 查询、POST 创建、PUT 更新、DELETE 删除。接口常用 JSON 传数据。

### 17.  ES的查询

ES 常用 JSON 格式的 Query DSL 写查询：`match` 做分词匹配，`term` 做精确词项匹配，`range` 查范围，`bool` 组合多个条件。比如搜商品名称一般用 match，查 keyword 类型的编号用 term。

### 18. 说说构建知识库相关的模块及关系

配置模块定义表、字段和指标；客户端模块管理连接；Repository 负责读写各个库；MetaKnowledgeService 把这些操作串起来；入口脚本负责启动。MySQL 存元数据，Qdrant 存向量，ES 存字段取值索引。

### 19. 构建知识库的同步脚本（入口脚本）的执行流程

入口是 build_meta_knowledge.py：初始化客户端 → 创建数据库会话和 Repository → 创建 Service → 调用 build()。成功后提交元数据库事务，异常时尝试回滚，最后关闭客户端。MySQL 的回滚不会撤销 ES 和 Qdrant 已写入的数据。

### 20. 构建知识库的业务函数的执行流程

build() 先清理旧元数据，再根据配置和数仓数据，把表、字段信息存入 MySQL；将字段的名称、描述和别名转成向量，存入 Qdrant；把需要同步的字段取值存入 ES；最后把指标及其字段关联存入 MySQL，再将指标的名称、描述和别名分批转成向量，连同指标信息一起存入 Qdrant。

### 21. 说说Graph中的几个核心组件

- 节点：处理某一步任务的函数，比如生成 SQL。
- 边：决定下一步走哪个节点，也可以按条件分支。
- 状态：各节点之间传递的数据，比如用户问题、SQL 和错误信息。
- 图：把节点和边组织起来，形成整个工作流程。

### 22. 说说节点函数的几个重要参数

项目里的节点主要接收 state 和 runtime。state 保存当前业务数据；runtime.context 提供数据库仓库、嵌入客户端等依赖，runtime.stream_writer 用来输出进度。节点通常返回一个字典，更新状态中的部分字段。

### 23. Graph编码的基本流程

定义 State 和 Context → 编写节点函数 → 创建 StateGraph → 注册节点 → 添加普通边和条件边，连接 START、END → compile() 编译 → 用 ainvoke() 或 astream() 异步运行。

### 24. 说一下项目中Graph编排的整个节点流程

提取关键词 → 并行召回字段、指标和字段取值 → 合并召回信息 → 并行筛选指标和表 → 补充上下文 → 生成 SQL → 校验 SQL。校验通过就执行并结束；有错误就校正 SQL，再回到校验节点。
